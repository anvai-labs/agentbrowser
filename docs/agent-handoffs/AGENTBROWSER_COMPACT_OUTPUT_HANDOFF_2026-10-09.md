# AgentBrowser compact-output handoff (Sandesha consumer, 2026-10-09)

The Sandesha session repeatedly had to observe the OVH Manager's user-policy dialog and six-row user table. `browser_observe` returned the full global navigation (roughly 190 elements) each time; the caller needed only the dialog, one row, or one menu item. A full JSON observation consumed thousands of output tokens even when the action involved one ref. The client currently works around this by filtering `structuredContent.elements` inside `functions.exec`, but the server still builds and transports the full snapshot and an occasional error is returned as a pretty-printed text content block.

Please design an opt-in compact projection for both CLI and MCP, preserving the current full response as the compatibility default. Suggested interface: `includeRoles`, `namePattern`, `scopeRef`, `limit`, and `fields` on observation, plus `compact: true` on action results. Return `sessionId`, `pageId`, `revision`, `url`, `truncated`, `continuation`, selected refs/roles/names/states, and error/operation IDs. Do not strip evidence needed to detect stale refs, incomplete snapshots, partial mutations, policy denial, or secret redaction. Projection should run after the existing observation/redaction path, not bypass it. Server-side filtering would reduce transport as well as model tokens; CLI `--compact` and MCP schema parity would make it discoverable.

Two concrete observations to review: `browser_observe` on the OVH Object Storage Users page emitted about 190 elements while the needed row/menu occupied fewer than 20. An observation immediately after a successful import returned an `INTERNAL` text block with an operation ID; the next observation worked. Keep such errors compact but machine-readable and retain reconciliation IDs. `browser_act` sometimes wraps compact JSON as a pretty-printed `content[0].text` instead of `structuredContent`; normalize where feasible.

Acceptance: measure serialized bytes and token estimate for the same OVH-style fixture before/after; verify the compact result supports ref-based click and stale-revision handling; verify truncated/degraded state and continuation are never hidden; verify password/secret fields stay redacted; preserve full mode and tests for both CLI and MCP. This is a tool ergonomics/performance issue, not authorization to change browser access or restart the active headed session.

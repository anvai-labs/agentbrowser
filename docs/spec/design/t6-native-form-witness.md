# C2b: native form evidence and named draft correlation

Base: develop `422fb62` (#245). Load forms/T6 and application/T4 only. This slice
adds bounded internal browser evidence, a service-scoped reader and a test-only
collector for the existing synthetic draft. Consent consumption and submission
remain separate follow-ups. Published 1.9.1 remains unchanged.

## Ownership and bounded capture

Extend the optional EnginePage read seam with `captureNativeForm({signal?})` and a
typed NativeFormEvidence envelope. Qualify Playwright Chromium first. Unsupported
engines refuse; no implicit fallback, public route, CLI command, arbitrary script,
selector payload or untyped metadata schema is added.

Reuse Playwright's existing formIdentityState, document token and node WeakMap for
document/form/control/fieldset identities. Share initialization and token assignment
with formControls observation. Initialization must not fork under concurrent reads.
Detect navigation and document-root replacement, including same-URL reload and
document.open. Identity is generated by the adapter, never taken from DOM IDs.

Capture one whole native main-document form: exact control inventory, hidden and
visible values, checked state, full bounded single-select options/selection, button
text, disabled/required/visibility metadata and selected-file metadata/digest. Refuse
extra forms, unassociated controls, option groups, custom widgets, frames, open shadow roots, unsupported
native input types, ambiguous/truncated inventories and multiple selected files.
DOM IDs and button text are untrusted data used only by the named contract validator.

Limit controls, strings, DOM inspection, option counts and total selected-file bytes
before allocating/reading them; at most 32KiB file bytes and 64KiB encoded finite JSON.
Hash actual captured File bytes inside the browser. After asynchronous hashing,
recheck the same document, form, controls, values/options and selected File objects;
equal filename/size is insufficient. Recheck cancellation before/after I/O and return
static errors without answers, filenames, browser exception messages or causes.
Closed shadow roots attached to ordinary elements are not discoverable through this
DOM seam: qualify only the audited cooperative fixture with no closed roots. Bound
DOM traversal before allocating inventories. This qualifies a cooperative application
and trusted adapter, not hostile-page attestation or a hard CPU-time sandbox.

## Service admission

`prepareNativeFormReadInScope(sessionId,pageId)` captures the exact service-owned
session/page objects, session incarnation, current admission and read method. Its
reader exposes narrow identity, assertAuthority and read(signal?). Require an existing
controlled admission, check owner identity before/after callbacks and awaits, make
observed revocation sticky, and use the existing authority read-drain tracking and
scope cancellation. Snapshot output with shared bounded JSON helpers before release.
No second authority, page registry, operation ledger or nested execute call.

## Named correlation and consistency collector (test support)

Trusted fixture configuration pins application adapter/resource/draft incarnation,
business/job identity, destination and intent to a captured service page, expected
origin/path and engine-generated document/form/control/fieldset identities. Pin every
named control's node and block association from the trusted initial capture; replacing
or moving controls requires new qualification, even if subsequent reads agree.
A page-displayed draft ID,
matching answers or caller-supplied correlation string cannot establish this pairing.
Capture the configuration privately before awaits; executing callers cannot repoint it.

Within one admission, compose existing prepared application evidence and the prepared
native reader: application A → native A → application B → native B. Require identical
complete application snapshots and identical native snapshots across the collection,
then recheck both authority fences. Equality means consistent observations, not proof
that no transient ABA change happened between reads. Each engine capture also checks its own async
file reads. Refuse unstable state; this collector does not retry actions.

Use the existing named data qualifier for exact application shape/completeness. Match
every named native field, distinct repeated-company blocks, hidden source, committed
selection, checkbox, optional referral and file name/type/size/digest. Require exactly
the supported inventory. Parse the fixture's bounded sync diagnostics strictly and
require the same version, zero pending writes and no failure. Those diagnostics stay
cooperative assertions; a broken handler with idle counters must still fail field/file
agreement. Keep the detached private aggregate under the shared canonical budget.

## Acceptance and remaining work

Failing-first engine tests cover healthy capture/identity reuse, hidden data and actual
bytes; same-URL navigation/root/form/control replacement; drift during hashing; bounds,
unsupported surfaces and cancellation. Service tests cover escaped readers, wrong/new
admissions, removed/replaced owners, revocation/cancel during capture, sanitized malformed
output and drain. Collector unit tests reject mismatched page/application identity and
malformed/conditional data. Real-browser collector tests reject broken handlers,
hidden/repeated-field drift, pending/failed uploads, owner drift, same-URL reload and
same-size same-name replacement bytes, with zero submission attempts.

Current evidence is not an atomic dispatch fence. Next bind an aggregate action-plus-
evidence envelope through the existing ApprovalGate and compare fresh evidence before
consumption. C3 requires app-owned atomic compare-and-submit and independent acceptance;
DOM precheck plus click cannot constrain hostile emitted payloads. T5 owns durability.
No live portal is qualified by these tests and no live application is submitted.

review, green PR checks, normal merge to develop and green post-merge checks. Update
